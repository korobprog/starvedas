# План: удобный буфер списков для куратора

## Цель

Сделать в кабинете куратора простой рабочий режим для копирования новых имён по услугам.

Куратор должен заходить в кабинет и сразу видеть не общую CRM, а раздел **«Списки»**. В нём показываются только услуги, по которым есть новые имена для обработки. Если новых имён по услуге нет, кнопка этой услуги не показывается.

## Как должен работать интерфейс

### 1. Вход в кабинет

Для пользователя с ролью `CURATOR` разделом по умолчанию должен быть:

```text
/cabinet?section=lists
```

Для администратора можно оставить текущий дефолтный раздел **«Обзор»**.

### 2. Первый экран раздела «Списки»

Куратор видит кнопки услуг с количеством новых имён:

```text
Выберите список

[Шраддха — 24]
[Накшатра — 8]
[Ганеша пуджа — 3]
```

Правила:

- показывать только услуги, где есть новые нескопированные имена;
- если по услуге новых имён нет — кнопки этой услуги нет;
- если новых имён нет вообще — показать простой текст:

```text
Новых имён для копирования пока нет.
```

### 3. Экран выбранной услуги

После клика по услуге куратор видит максимально простой экран без лишних данных.

Пример:

```text
Шраддха

[Скопировать имена]

Иванов Иван
Петров Пётр
Нерожденный ребенок - Петровой Надежды 1

[Скопировал]
```

На этом экране **не должно быть**:

- номера заказа;
- заказчика;
- контактов;
- статусов;
- таблиц;
- комментариев;
- переписки;
- карточек списков;
- служебной информации.

Только:

1. название услуги;
2. кнопка копирования;
3. чистый список имён по порядку;
4. кнопка подтверждения **«Скопировал»**.

## Как формировать список имён

Список должен быть обычным текстом, одна строка — одно имя.

Порядок:

1. обычные участники из `order.participants` в порядке `sortOrder`;
2. затем детские/нерождённые записи из `order.childRecords`.

Пример итогового текста:

```text
Иванов Иван
Петров Пётр
Нерожденный ребенок - Петровой Надежды 1
```

Для детских/нерождённых записей использовать текущую существующую логику форматирования:

```ts
formatChildRecordLines(...)
```

Важно:

- пустые строки не показывать;
- если детская/нерождённая запись уже есть среди участников, не дублировать её;
- сохранить порядок поступления имён;
- копироваться должен именно этот чистый текст без заголовков и метаданных.

## Подтверждение копирования

Кнопка **«Скопировать имена»** только копирует текст в буфер браузера.

Она не должна менять базу данных, потому что копирование может не сработать.

После того как куратор убедился, что имена скопированы, он нажимает:

```text
[Скопировал]
```

Только после этого система должна считать имена отработанными куратором.

## Что происходит после «Скопировал»

После подтверждения система должна:

1. пометить соответствующие списки как взятые/скопированные куратором;
2. убрать эти имена из активного буфера куратора;
3. убрать эти имена из активного буфера статиста, чтобы не было дублей;
4. если по выбранной услуге больше нет новых имён — кнопка услуги исчезает;
5. если позже по этой услуге придут новые оплаченные имена — кнопка услуги снова появляется.

Предпочтительно использовать или расширить существующие поля `ParticipantList`:

- `claimedByRole`;
- `claimedByCuratorId`;
- `claimedByUserId`;
- `claimedAt`;
- `copiedAt`.

Логика для новых имён куратора может быть такой:

```ts
list.status === ParticipantListStatus.NEW && !list.claimedByRole
```

или, если нужно учитывать отдельное поле копирования:

```ts
!list.copiedAt
```

Перед реализацией нужно сверить это с текущей логикой буфера статиста.

## Групповое подтверждение по услуге

Так как куратор будет копировать сразу все новые имена выбранной услуги, лучше сделать отдельное server action:

```ts
claimCuratorServiceParticipantListsAction
```

Она принимает:

```ts
serviceId
```

И помечает все новые списки этой услуги для текущего куратора как скопированные.

Пример обновления:

```ts
claimedByRole = CURATOR
claimedByCuratorId = curator.id
claimedByUserId = user.id
claimedAt = now
copiedAt = now
```

## Telegram-уведомления

Нужно добавить мониторинг раз в час.

Система должна проверять по каждому куратору количество новых нескопированных имён.

Если новые имена есть, отправлять куратору сообщение в Telegram-бот:

```text
У вас новые имена для обработки: 24

Шраддха: 18
Накшатра: 6
```

В сообщении должна быть кнопка:

```text
Открыть списки
```

Кнопка открывает кабинет/mini app сразу в раздел списков:

```text
/cabinet?section=lists
```

## Защита от дублей и спама

Минимальный вариант:

- раз в час отправлять уведомление, если есть новые имена.

Желательный вариант:

- не отправлять одно и то же уведомление каждый час без изменений;
- хранить время последнего уведомления или количество имён на момент последнего уведомления;
- повторять уведомление только если появились новые имена или прошло достаточно времени.

Возможное поле для будущей доработки:

```ts
lastParticipantListReminderAt
```

## Рекомендуемый порядок реализации

1. Сделать вход куратора сразу в раздел `lists`.
2. Сгруппировать новые нескопированные имена по услугам.
3. Показать кнопки услуг с количеством имён.
4. Сделать экран выбранной услуги с чистым списком имён.
5. Сделать копирование чистого текста.
6. Сделать кнопку **«Скопировал»** и bulk server action.
7. Проверить, что после подтверждения имена исчезают у куратора.
8. Проверить, что после подтверждения имена не попадают статисту как новые.
9. Добавить Telegram-уведомление раз в час.
10. Добавить защиту от повторных одинаковых уведомлений.
