# План реализации отчета продаж кураторов

## Цель

Сделать в админке отдельный отчет, где администратор видит продажи:

- каждого куратора;
- каждой партнерской ссылки/источника внутри куратора;
- по продуктам и мероприятиям;
- с детализацией до конкретной продажи и клиента.

Отчет должен отвечать на вопросы:

- сколько продаж сделал каждый куратор;
- сколько продаж принес каждый партнер/источник куратора;
- какие продукты и мероприятия продавались;
- кто клиент;
- какая сумма, валюта и контакты клиента.

## Важное решение по партнерам

Отдельную модель `Partner` на первом этапе не добавляем.

В проекте уже есть механизм партнерских ссылок куратора:

- `ReferralLink.title` — название партнера/источника;
- `ReferralLink.slug` — код ссылки;
- `ReferralLink.curatorId` — владелец ссылки;
- `ReferralLink.createdByCurator` — ссылка создана куратором;
- `ReferralLink.isPrimary` — основная ссылка куратора.

Продажи уже сохраняют источник через:

- `Order.curatorId`;
- `Order.referralSlug`.

Поэтому в отчете:

- **куратор** = `Order.curatorId`;
- **партнер / источник** = `ReferralLink.title`;
- **код ссылки** = `Order.referralSlug`;
- связь строится через `Order.referralSlug === ReferralLink.slug`.

Если `ReferralLink.title` пустой, показывать `referralSlug`. Если ссылки нет — `Без ссылки`.

## Фильтры

Фильтры делать через `searchParams`, как на существующих админских страницах.

### Основные фильтры

1. **Период**
   - чекбокс `Использовать период`;
   - `dateFrom`;
   - `dateTo`.

2. **Куратор**
   - `curatorId`;
   - варианты: `Все кураторы` + список кураторов.

3. **Партнер / источник**
   - `referralSlug`;
   - варианты: `Все партнерские ссылки` + `ReferralLink.title`.

4. **Продукт**
   - `serviceId`;
   - варианты: `Все продукты` + список `Service`.

5. **Мероприятие / опция**
   - на первом этапе можно сделать текстовый фильтр по `OrderServiceOption.titleSnapshot`;
   - позже можно заменить на select по `ServiceOption`.

6. **Статус**
   - по умолчанию `PAID`;
   - варианты:
     - `PAID`;
     - `REFUNDED`;
     - `WAITING_PAYMENT_VERIFICATION`;
     - `Все статусы`.

7. **ФИО клиента**
   - поиск по `Order.customerName`.

8. **Email**
   - поиск по `Order.customerEmail`.

9. **Телефон**
   - поиск по `Order.customerPhone`.

10. **Источник сайта**
    - `sourceDomain`;
    - варианты:
      - все;
      - `starvedas.ru`;
      - `chintamanidhama.ru`.

## Логика дат

Для оплаченных продаж предпочтительно использовать:

```text
Payment.paidAt
```

Если `Payment.paidAt` пустой, fallback:

```text
Order.createdAt
```

На первом этапе допускается фильтрация по `Order.createdAt`, чтобы не усложнять запрос. Но в интерфейсе лучше подписать как:

```text
Дата продажи / создания заказа
```

## Сводка по кураторам

Отдельный блок таблицы:

```text
Куратор
Продаж
Клиентов
Партнеров / источников
Сумма
Возвраты
Итого
```

Логика:

- продажа считается по заказам со статусом `PAID`;
- возврат считается по заказам со статусом `REFUNDED`;
- итог = оплачено - возвраты.

## Сводка по партнерским ссылкам

Отдельный блок таблицы:

```text
Куратор
Партнер / источник
Код ссылки
Продаж
Клиентов
Сумма
Возвраты
Итого
```

Группировка:

```text
curatorId + referralSlug
```

Название источника брать из:

```text
ReferralLink.title
```

Fallback:

```text
ReferralLink.slug / Order.referralSlug / Без ссылки
```
